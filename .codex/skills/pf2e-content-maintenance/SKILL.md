---
name: pf2e-content-maintenance
description: Import, audit, repair, or link PF2E compendium records while preserving mechanics, editability, sources, and licensing.
---

Trace a published record back to `../structured-modules` and its builder or
generated catalog before editing. Fix the reusable conversion when a defect
appears across multiple records; use a narrow supplement only for genuine
source exceptions.

Use current licensed rules and errata as the mechanical authority. AoN is useful
for identifying expected links and current presentation; Foundry data is useful
for structured fields, IDs, ranges, acuity, and embedded relationships. Neither
source alone proves that distributable prose belongs in this repository.

Preserve source book/page data when reliable, internal Encounter+ links,
Remaster terminology, and the applicable ORC/OGL markers. Every mechanic shown
on the creature, item, hazard, vehicle, spell, or other record should be
editable unless it is exclusively a supported map-load action.

Rebuild the affected public packs, extend an existing domain regression for the
observed failure, and run `python3 tools/eplus_dev.py check --json`. Do not add a
new standalone test file when the invariant belongs in an existing suite.
